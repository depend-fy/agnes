# 答辩材料与架构说明（阶段 7）

> 本文件是给比赛/答辩用的材料：系统设计、关键技术决策、可追溯性、指标口径、已知局限、升级路径。
> 所有"结果"均来自真实运行；没有真实数据的地方都明确标注"未测/初步/桩"。

---

## 1. 项目一句话
面向 AI 生成文本的**多角色幻觉检测、证据溯源、问题归因、基于证据自动修正与独立复核** Demo。
核心立场：**无证据 ≠ 错误，系统绝不编造证据或武断判错。**

## 2. 核心设计原则（答辩必讲）
1. **无证据 ≠ 错误**：查不到可信证据 → 标记"暂无法核验/证据不足"，绝不判错。
2. **不伪造证据**：修正在无证据时不生成文本，标注"需人工"。
3. **不展示未校准概率**：只展示有明确含义的状态 + 定性风险，不报伪精确概率。
4. **区分真实多模型 vs 单模型模拟**：`model_tag` 字段区分，桩/模拟在 UI 里明确标注。
5. **全程可追溯**：每条证据带来源名/URL/检索时间；每个角色判断带 model_tag。

## 3. 架构（六段式管线）
```
输入文本
  → ① 原子事实主张提取（claims/extractor，规则桩 → 可换 LLM）
  → ② 外部证据检索（retrieval：Crossref + OpenAlex，失败回退证据快照）
  → ③ 多角色协同检测（roles：事实审查员/Agnes + 证据审查员/DeepSeek + 独立复核员/DeepSeek）
  → ④ 证据-主张匹配 + 六态八类归因（attribution/classifier）
  → ⑤ 基于证据修正（correction/generator）
  → ⑥ 独立复核修正（review/reviewer）
  → 检测报告（report/assembler + Streamlit）
```
每段都是**纯函数**，可独立调用、独立测试（不依赖 Streamlit 状态）。

## 4. 关键技术决策（答辩问答素材）

**Q: 为什么是"多角色"而不是单模型？**
A: 让不同角色看到不同信息（事实审查员看主张+原文；证据审查员看证据；独立复核员看修正+前序判断），减少单一视角偏差。当前 Agnes/DeepSeek 是两个真实端点；若只有单模型，系统会明确标注"单模型模拟"，不假装是多模型。

**Q: 怎么保证不编造证据？**
A: 三层保障：(1) 检索只返回真实 Crossref/OpenAlex 结果，查无就是查无；(2) 分类器保守——摘要层面不足以判断时落"证据不足"，不升级成"已核实"；(3) 修正在证据为空/不足时拒绝生成文本，标注需人工。

**Q: 现场断网怎么办？**
A: 证据快照兜底（`retrieval/snapshot.py`）：先真实检索，失败/空时回退 `examples/evidence_snapshot.json`（联网时预取的真实证据），Demo 不卡死、不崩。报告页标注证据来源是"实时检索"还是"本地预取快照"，不谎称刚检索。

**Q: 成本怎么算的？**
A: `metrics.py` 按 token × 单价表估，未知模型记 0 并标注"单价未配置"，绝不编造数字。报告页显示"成本估算"，注明是量级估算非账单。

**Q: 指标怎么来的？可信吗？**
A: 评测必须基于**人工标注测试集**（`examples/labeled_cases.json`），指标由真实运行对比标注算出。样本量 < 10 自动标注"初步结果"；无标注数据则明确"指标不可计算"，不编造准确率。

## 5. 指标口径（明确边界）
| 指标 | 计算方式 | 前提 |
|---|---|---|
| 幻觉检测 精确率/召回率/误报率 | 混淆矩阵（系统判有问题 vs 标注） | 需标注测试集 |
| 问题类型 F1 | 八类标签命中 | 需标注 |
| 修正成功率 | 有修正文本且复核通过 | 需修正发生 |
| 可追溯率 | 判定带 evidence_id/来源链接占比 | 直接可算 |
| 平均延迟/成本 | provider 真实累计 | 真实 LLM 调用 |

> 诚实声明：当前评测集规模小（4 条标注），所有指标为**初步结果**。被测模型不给自己打分。

## 6. 已知局限（主动讲，加分）
- 检索只到摘要/元数据层，未获取全文；摘要不足以判断时落"证据不足/暂无法核验"。
- 修正是单次生成，未做无限循环重生成；复核失败只提示风险。
- 角色判断按整体一条输出，未逐 claim 拆分。
- 指标为初步结果，未做大规模基线对比。

## 7. 升级路径（架构预留，未实际搭建）
当前是 Streamlit 单体。升级为完整 Web 产品的路径：
```
FastAPI 后端（/api/verify、/api/evaluate，复用 pipeline.run 纯函数）
  + 前端（React/Next）
  + 持久化（SQLite 存 DetectionReport）
  + 并发（每请求独立 provider 实例，避免共享累计统计）
```
pipeline 各段是纯函数，可被 FastAPI 直接调用，无需重写核心逻辑。

## 8. 现场演示脚本（建议 5 分钟）
1. 打开 `http://localhost:8501`，展示顶部模式说明（live + 双 key + 快照兜底）。
2. 选"真实 DOI（完整链路演示）"案例，点"开始检测"，逐段讲 ①-⑥。
3. 强调"检索到的证据"是真 Crossref 命中（Nature 2013），来源可点。
4. 强调"修正建议"只改有证据的部分，保留已支持内容。
5. 强调"独立复核"检查修正是否引入新错误。
6. 点"运行评测"，展示指标 + 初步结果标注（诚实声明样本小）。
7. 兜底话术：若现场网络慢，说"证据快照已预取，断网也能走完全链路"。
